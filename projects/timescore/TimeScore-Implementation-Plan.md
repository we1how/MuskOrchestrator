## 一、核心决策确认

### 1.1 定价策略: Freemium + 买断制

| 版本 | 价格 | 功能 |
|------|------|------|
| **免费版** | ¥0 | 本地存储、基础记录、3个心愿上限、7天历史 |
| **Pro版** | $4.99 (一次性) | iCloud同步、无限心愿、完整历史、数据导出、高级统计 |

**为什么选择买断制而非订阅?**
- 个人开发者维护订阅成本高(服务器、税务处理)
- 国内用户对订阅制敏感，买断转化率更高
- $4.99 = 一杯奶茶价格，决策门槛低
- 符合"反野心创业法": 先做小，降低用户决策成本

### 1.2 iCloud作为付费点的策略

**免费版提示策略**:
```
第1次记录: 正常流程
第5次记录: 底部提示"数据仅存储在本地"
第10次记录: 弹窗:"已记录10个行为，开启iCloud同步防止数据丢失"
换机/卸载警告: 明确告知"数据将会丢失"
```

**不强制但制造焦虑**，让用户主动选择购买。

### 1.3 设计规范

#### 配色方案
```
主色:     #2E7D32 (深绿)   - 成长、时间
辅助色:   #FFC107 (琥珀黄) - 能量、奖励
背景色:   #FAFAFA (浅灰)   - 干净、专注
警示色:   #F44336 (红色)   - D级行为、删除
文字色:   #212121 (深灰)   - 主文字
次要文字: #757575 (中灰)   - 辅助信息
```

**为什么选择绿色?**
- 区别于番茄钟的焦虑红色
- 代表成长、正向反馈
- 适合Dark Mode自动适配

#### Logo方案
**推荐**: 极简文字Logo "TS"
- 使用SF Pro Rounded字体
- T和S用深绿色(#2E7D32)
- 圆角处理，体现友好感
- App Icon: 绿色圆角方形背景 + 白色TS文字

**实现方式**: 无需设计师，用SF Symbols + SwiftUI绘制

## 二、公式优化方案(优化.md修订版)

### 2.1 当前公式问题

| 问题 | 当前值 | 建议值 | 原因 |
|------|--------|--------|------|
| S级消耗过高 | 0.35/min | **0.25/min** | 120精力只能工作5.7小时，过少 |
| C/D惩罚过轻 | -0.5/-1.0 | **-0.8/-1.5** | 惩罚应大于收益，否则用户不在乎 |
| R级收益过高 | 0.2-0.4 | **0.1-0.2** | 休息不应比B级工作收益高 |
| 精力恢复过慢 | 0.02/min | **0.08/min** | 从0恢复满需要4天，不合理 |

### 2.2 新配置表

```swift
// ScoringViewModel.swift
static let gradeConfig: [String: (baseScore: Double, energyCost: Double)] = [
    // 正向行为
    "S":  (baseScore: 1.8,  energyCost: 0.25),  // 降低消耗
    "A":  (baseScore: 1.2,  energyCost: 0.25),  // 保持不变
    "B":  (baseScore: 0.7,  energyCost: 0.18),  // 保持不变

    // 负面行为 - 加重惩罚
    "C":  (baseScore: -0.8, energyCost: 0.10),  // -0.5 → -0.8
    "D":  (baseScore: -1.5, energyCost: 0.15),  // -1.0 → -1.5

    // 恢复行为 - 降低收益
    "R1": (baseScore: 0.1,  energyCost: -0.10), // 0.2 → 0.1
    "R2": (baseScore: 0.15, energyCost: -0.20), // 0.3 → 0.15
    "R3": (baseScore: 0.2,  energyCost: -0.30)  // 0.4 → 0.2
]
```

### 2.3 精力系统优化

```swift
// EnergyViewModel.swift
/// 自动恢复速率（每分钟）
static let recoveryRate: Double = 0.08  // 0.02 → 0.08 (每小时+4.8点)

/// 睡眠重置逻辑（新增）
func sleepReset() -> Double {
    // 睡眠后完全恢复 + 额外奖励
    return EnergyViewModel.maxEnergy + 10  // 120 + 10 = 130(溢出部分丢弃)
}
```

**恢复时间对比**:
- 原方案: 120 / (0.02×60) = 100小时 = 4.2天
- 新方案: 120 / (0.08×60) = 25小时 = 1天

### 2.4 放弃"疲劳系数"(与优化.md不同)

**原因**:
- 增加理解复杂度
- 首版应保持简单
- 可作为Pro版"高级统计"功能

## 五、与优化.md的差异说明

| 项目 | 优化.md建议 | 本方案 | 理由 |
|------|-------------|--------|------|
| 疲劳系数 | 新增 | **放弃** | 首版保持简单，放Pro版 |
| R级分数 | 不加分 | **保留低分** | 避免用户不记录休息 |
| 定价模式 | $1.99/月订阅 | **$4.99买断** | 国内订阅接受度低 |
| 恢复速率 | 每小时+5 | **每小时+4.8** | 保持整数计算方便 |
| 目标市场 | 国内或海外 | **国内为主+海外同步** | 产品概念全球通用 |
