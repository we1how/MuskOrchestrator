# Project-First Mindset - 项目先行思维

> "The best startups don't start as startups. They start as projects."
> "The way to succeed in a startup is not to be an expert on startups, but to be an expert on your users and the problem you're solving for them." —— Paul Graham

---

## 概述

项目先行思维是一种反直觉的创业和创造方法论。与其寻找"创业想法"或"商业机会"，不如专注于解决你自己真正遇到的问题。最好的公司（Google、Facebook、Apple、Microsoft）都始于创始人想解决自己的问题的项目，而非刻意规划的创业。

---

## 核心概念

### 起源
Paul Graham在2025年的文章"How to Start Google"中提出：
> "如果你告诉Larry Page和Sergey Brin，他们即将创办的公司有一天会价值超过万亿美元，他们的头会爆炸。"

Google创始人最初只是想改进搜索，Facebook创始人只是想修复哈佛的通讯录。他们不是在"创业"，只是在解决自己的问题。

### 两种路径的本质区别

| 错误路径（创业导向） | 正确路径（项目导向） |
|-------------------|-------------------|
| 寻找"创业想法" | 解决自己遇到的问题 |
| 写商业计划书 | 直接动手构建 |
| 思考估值和融资 | 让朋友真正想用你的产品 |
| 为抽象"用户"构建 | 为自己和朋友构建 |
| 追逐趋势（AI、区块链） | 追随兴趣和直觉 |

---

## 执行框架

### Phase 1: 识别真正的问题
1. 问自己："我遇到什么烦人的问题？"
2. 观察："我的朋友抱怨什么？"
3. 检验：这是真实存在的问题，还是想象的需求？
4. 标准：如果关掉解决方案，你会难过吗？

### Phase 2: 构建项目（非产品）
1. 不要想"这能变成公司吗"
2. 只问自己："我想解决这个问题"
3. 为自己和直接朋友构建
4. 追求：朋友不是因为loyalty使用，而是真正需要

### Phase 3: 项目驱动学习
1. 遇到不会的技术 → 在项目中学习
2. 比课堂学习快得多（动力驱动）
3. 寻找联合创始人 → 通过项目合作发现
4. 迭代：构建 → 使用 → 改进 → 扩展

### Phase 4: 自然生长（或停止）
1. 如果朋友想要更多 → 扩展给更多人
2. 如果需求真实 → 可能变成公司
3. 如果没人需要 → 快速失败，低成本试错
4. 关键：不要强迫它成为公司

## 决策检查清单

```
□ 我是在解决自己真正遇到的问题吗？
□ 我构建的东西，我自己真的想要吗？
□ 我是在"创业"还是在"做项目"？
□ 我的朋友是真正需要，还是出于loyalty使用？
□ 如果关掉这个项目，我会难过吗？
□ 我是在追逐趋势，还是在追随兴趣？
□ 我是在消费（玩游戏/刷内容），还是在生产（做游戏/做内容）？
```

## 启动Google需要的三件事

```
1. 精通某种技术
   └── 方法：做自己的项目（不是上课）
   └── 选择：追随兴趣，而非追逐趋势
   └── 默认推荐：编程（过去30年创业公司的中位数来源）

2. 构建什么的想法
   └── 方法：寻找问题，最好是你自己的问题
   └── 检验：你的朋友是否真正想要（不只是出于loyalty）
   └── 信号：如果关掉它，朋友会真的难过

3. 联合创始人
   └── 方法：通过项目合作发现
   └── 标准：技术能力 + 合作默契
   └── 最佳来源：顶尖大学（因为筛选机制聚集了聪明且坚定的人）
```

## 实际应用对比

| 场景 | 创业导向做法 | 项目导向做法 |
|------|-------------|-------------|
| 想做一个产品 | 研究市场、写商业计划 | 解决自己遇到的问题 |
| 学习新技术 | 上课、读书、考证 | 开始一个用该技术的项目 |
| 寻找合伙人 | 参加创业活动、networking | 一起做项目，自然发现 |
| 验证想法 | 用户调研、市场分析 | 构建出来，让朋友用 |
| 评估进展 | 用户数、收入、融资 | 自己和朋友是否还想用 |

## 关键洞察

### 1. 课堂教育的局限性
> "你可以在顶尖大学获得计算机科学学位，但仍然不擅长编程。这就是为什么科技公司在你入职前都要你做编程测试。"

**项目驱动学习**比课堂学习快得多，因为：
- 遇到想实现的功能但不知道怎么做 → 解决问题的动力驱动学习
- 比课堂学习速度快得多
- 产出是可用的项目，而非只是成绩

### 2. 最佳创业想法的三个特征
1. **创始人自己想要**
2. **创始人自己能构建**
3. **很少人意识到值得做**

**为什么"自己想要"如此重要**：
- 确保问题真实存在（而非想象）
- 让你成为专家用户
- 深度理解需求，而非表面观察

### 3. "活在未来，然后构建缺失的东西"
Paul Buchheit的这句话是创业想法的终极来源：
- 如果你精通技术并"活在未来"
- 你会注意到什么东西坏了或缺失了
- 你能在其他人意识到需要之前构建它

**类比**：到处都是"卡住的门"（sticking doors）——等待被修复的问题。

## 触发条件

- 想创业但不知道做什么
- 学习新技术但缺乏动力
- 感觉在"准备"而非"行动"
- 想从消费者转变为生产者
- 寻找联合创始人
- 验证创业想法

---

## 核心输出

1. **一个解决真实问题的项目** - 为自己和朋友构建
2. **通过项目获得的技术能力** - 比课堂学习更深入
3. **潜在的联合创始人** - 通过合作发现
4. **自然生长的机会** - 如果需求真实，可能变成公司
