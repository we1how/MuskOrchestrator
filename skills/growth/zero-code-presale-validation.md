# 零代码预售验证模型 (Zero-Code Presale Validation Model)

> **先收钱，再开发。用48小时验证6个月的需求。**

---

## 核心概念

传统产品开发路径：
```
开发MVP (3-6月) → 寻找客户 → 迭代产品
     ↓
高风险：可能无人需要
```

预售验证路径：
```
预售验证 (48小时) → 手动服务 → 产品化
     ↓
低风险：已验证付费意愿
```

---

## 适用场景

- [ ] 新产品方向验证
- [ ] 从服务转型SaaS
- [ ] 现有用户群的新需求探索
- [ ] 高风险产品决策前的低成本验证
- [ ] 资源有限但需要快速验证市场

---

## 执行SOP

### Phase 1: 用户访谈（Week 1-2）

**目标**: 发现真实痛点，而非表面需求

**步骤**:
1. 与10-20个现有/潜在用户深度沟通
2. 使用"5个为什么"挖掘根因
3. 记录用户原话（用于后续文案）
4. 识别：用户要的是"监控"还是"执行"？

**关键问题**:
- "你目前如何解决这个问题？"
- "如果这个问题解决了，对你意味着什么？"
- "你愿意为解决这个问题付多少钱？"
- "什么情况下你会立即付费？"

**输出物**:
- 用户痛点清单（按频率排序）
- 用户原话库（用于营销文案）
- 定价敏感度数据

---

### Phase 2: 设计预售方案（Week 2-3）

**定价策略**:

| 要素 | 建议 | 案例参考 |
|------|------|----------|
| 定价 | 月费的3-6倍 | Vismore: $399/月 x 3个月 |
| 合约期 | 3个月 | 足够验证，不会太长 |
| 退款保证 | 结果不好全额退款 | 降低决策门槛 |
| 名额限制 | 5-10人 | 确保交付质量 |

**筛选标准**:
- 有明确痛点（非"好奇尝试"）
- 有决策权（能快速决定）
- 有预算（价格不敏感）
- 愿意反馈（能配合迭代）

**预售文案模板**:
```markdown
## [产品名] 早期用户招募

我们正在开发[产品描述]，现招募7位早期用户。

**你将获得**:
- 3个月一对一服务
- 每周策略会议
- 结果不好全额退款

**投资**: $[价格] / 3个月
**名额**: 仅7人

**申请条件**:
- [条件1]
- [条件2]
- [条件3]

**申请方式**: [链接/邮箱]
```

---

### Phase 3: 启动预售（Week 3-4）

**渠道优先级**:

| 渠道 | 优先级 | 原因 |
|------|--------|------|
| 现有用户群 | P0 | 已有信任基础，转化率最高 |
| 私域社群 | P1 | 关系链传播，质量可控 |
| 付费社群 | P2 | 用户质量高，但需建立信任 |
| 公开渠道 | P3 | 冷启动难度大，作为补充 |

**时间线**:
- **Day 1**: 向现有用户群发邀请
- **Day 2-3**: 收集申请，初步筛选
- **Day 4-5**: 一对一沟通，确认意向
- **Day 6-7**: 关闭预售，开始服务

**关键指标**:
- 申请数 > 30（证明需求存在）
- 录取率 < 20%（严格筛选）
- 付费转化率 > 50%（验证付费意愿）

---

### Phase 4: 手动服务验证（Month 1-3）

**服务模式**:
- 完全手动执行（不开发任何代码）
- 每周策略会议
- 实时反馈收集
- 流程文档化

**关键任务**:
1. **交付结果**（证明方法论有效）
2. **记录流程**（为自动化做准备）
3. **收集反馈**（识别产品化机会）
4. **建立案例**（为后续营销准备）

**文档模板**:
```markdown
## 服务日志 - [客户名]

**日期**: YYYY-MM-DD
**任务**: [具体执行内容]
**耗时**: X小时
**结果**: [量化结果]
**客户反馈**: [原话]
**可自动化**: [是/否] [原因]
```

---

### Phase 5: 产品化（Month 3+）

**产品化决策标准**:
- [ ] 至少3个客户验证方法论有效
- [ ] 流程已标准化（SOP文档化）
- [ ] 识别出可自动化的环节
- [ ] 客户愿意推荐他人

**MVP功能优先级**:
1. 核心自动化功能（解决80%重复工作）
2. 客户自助界面（减少人工介入）
3. 数据/报告功能（展示价值）
4. 高级功能（差异化竞争）

**定价调整**:
- 服务价格 → SaaS订阅价格（通常降低50-70%）
- 增加自助选项（降低服务成本）
- 保留高端服务（高价值客户）

## 关键原则

### 1. 严格筛选 > 广泛撒网

**反直觉真相**: 50个申请录取7人，比录取30人效果更好。

**原因**:
- 确保交付质量
- 获得高质量反馈
- 建立稀缺性和 exclusivity
- 避免"好奇尝试者"占用资源

**执行**:
- 设置申请门槛（问卷筛选）
- 一对一面试确认意向
- 明确告知"我们不接受所有人"

---

### 2. 执行 > 监控

**用户真实需求**: 不要"告诉我问题"，要"帮我解决问题"。

| 竞品做法 | 你的差异化 |
|---------|-----------|
| "你排名第7" | "这是提升到第1的具体方案" |
| 数据展示 | 策略建议 |
| 问题诊断 | 问题解决 |

---

### 3. 手动先行 > 自动化优先

**常见错误**: 跳过手动验证直接开发产品。

**后果**:
- 把错误假设编码进产品
- 开发3个月发现方向错误
- 产品功能不符合真实需求

**正确路径**:
```
手动服务 → 验证方法论 → 识别可自动化环节 → 产品开发
```

---

### 4. 退款保证 = 信任加速器

**心理学原理**: 降低感知风险，加速决策。

**话术模板**:
> "如果3个月内没有看到[具体结果]，全额退款，不问原因。"

**注意**:
- 明确结果标准（避免争议）
- 设定时间边界（3个月）
- 确保自己能交付（不要过度承诺）

---

## 风险与应对

| 风险 | 概率 | 应对策略 |
|------|------|----------|
| 预售失败 | 中 | 申请数<10说明需求不足，及时止损 |
| 交付困难 | 中 | 严格筛选，控制名额 |
| 方法论无效 | 低 | 小范围验证，快速迭代 |
| 产品化困难 | 中 | 保留部分服务，渐进自动化 |

## 工具与模板

### 申请筛选问卷模板
```markdown
## [产品名] 早期用户申请

**基本信息**
- 姓名：
- 公司：
- 角色：
- 邮箱：

**痛点确认**
- 你目前如何解决[问题]？
- 这个问题每月给你造成多少损失？
- 你尝试过哪些解决方案？效果如何？

**付费意愿**
- 如果[结果]能实现，你愿意付多少钱？
- 决策周期是多久？
- 是否需要他人批准？

**参与度**
- 每周能投入多少时间配合？
- 是否愿意提供详细反馈？
- 成功后是否愿意作为案例？
```

### 服务协议模板
```markdown
## 服务协议

**服务方**: [你的名字/公司]
**客户方**: [客户名]
**服务期**: 3个月 (YYYY-MM-DD 至 YYYY-MM-DD)
**费用**: $[金额] (预付)

**服务内容**:
- [具体服务1]
- [具体服务2]
- [具体服务3]

**预期结果**:
- [可量化结果1]
- [可量化结果2]

**退款条款**:
如果3个月内未达到[结果标准]，客户可申请全额退款。

**签名**: ___________ 日期: ___________
```

## 检查清单

### 预售前
- [ ] 已完成10+用户访谈
- [ ] 痛点已验证（非假设）
- [ ] 定价已测试（用户愿意付）
- [ ] 服务SOP已初步设计
- [ ] 申请渠道已准备

### 预售中
- [ ] 申请数 > 30
- [ ] 一对一沟通 > 10人
- [ ] 录取率 < 20%
- [ ] 付费转化率 > 50%

### 服务期
- [ ] 每周客户会议
- [ ] 流程文档化
- [ ] 反馈收集
- [ ] 案例积累

### 产品化前
- [ ] 至少3个成功案例
- [ ] 流程已标准化
- [ ] 自动化环节已识别
- [ ] 客户愿意推荐
