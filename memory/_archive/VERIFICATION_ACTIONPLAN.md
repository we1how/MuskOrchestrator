**目标**: 证明或否定 CostModelV2 对三个流动性等级的适用性

**方法论**:
```

### P0-3: 诊断系统延迟实测

**目标**: 测量诊断系统的真实延迟，包括 P95、P99、并发情况

**方法论**:
```
实验环境:
- 硬件: 测试服务器（与生产类似的CPU/内存）
- 数据: 2024年全年真实市场数据

测试场景:
1. 单个检测器延迟（顺序执行）
   └─ 各运行100次，记录每次耗时
   
2. 6个检测器并行执行
   └─ 测量总耗时（取最慢的）
   
3. 并发处理（同时诊断50只股票）
   └─ 测量吞吐量 (stocks/sec)
   └─ 测量延迟 (P50, P95, P99)
   
4. 加上I/O延迟（从数据库读状态）
   └─ 包括数据库查询时间
   └─ 包括网络往返延迟

测试代码框架:
```python
import time
import numpy as np

latencies = []
for i in range(100):
    t0 = time.perf_counter()
    result = diagnostics.detect(state)
    t1 = time.perf_counter()
    latencies.append((t1-t0)*1000)  # convert to ms

print(f"P50: {np.percentile(latencies, 50):.2f}ms")
print(f"P95: {np.percentile(latencies, 95):.2f}ms")
print(f"P99: {np.percentile(latencies, 99):.2f}ms")
```

**验收标准**:
- [ ] 测量了 6 个检测器的各自延迟
- [ ] 测量了并行执行的总延迟
- [ ] 测量了并发情况下的 P95/P99
- [ ] 包括了 I/O 延迟的完整链路延迟
- [ ] 结果表明延迟 < 1000ms（自动调整阈值）或 >= 1000ms（需要人工）

### P0-4: 6个检测器的虚警率统计

**目标**: 量化每个诊断检测器的虚警率（false alarm rate）和检出率（sensitivity）

**方法论**:
```
定义:
- True Positive (TP): 检测器识别出真实的失效
- False Positive (FP): 检测器虚警（不是真实失效）
- False Negative (FN): 检测器漏检（有失效但没检出）

评估方法 - "金标准"比较法:
1. 对2024年全年回测数据，计算理想的"基线"性能
   - 用穷举搜索找到最优参数
   - 记录该参数对应的 Sharpe
   
2. 在该数据上运行诊断器
   - 记录诊断器的告警时间 t_alert
   - 在 t_alert 之后的5天，比较：
     * 实际 Sharpe（用最优参数）
     * 当前 Sharpe（用被诊断的参数）
   
3. 如果两者差异 > 0.1（Sharpe差），则认为"TP"
   否则认为"FP（虚警）"

虚警率计算:
false_alarm_rate = FP / (TP + FP)
```

**验收标准**:
- [ ] 统计了全年 100+ 次诊断告警事件
- [ ] 对每个检测器计算了虚警率
- [ ] 虚警率报告应该明确标注"高风险"检测器（虚警率 > 20%）
- [ ] 识别出哪些检测器可靠（虚警率 < 5%），哪些需要改进

**交付物**:
```

检测器,总告警次数,TP(真实),FP(虚警),虚警率(%),可信度评级

结论: 
- ✓ 可信的检测器 (虚警率<10%): Kalman漂移, Sharpe虚假, HMM延迟
- △ 需要改进的 (虚警率 10-20%): RLS过激

### P0-5: Sharpe复现率期望修正

**目标**: 基于理论和历史数据，重新评估 Paper→Live Sharpe 复现率的合理范围

**方法论**:
```
复现率拆解模型:
observed_live_sharpe = 
    backtest_sharpe × (1 - information_leakage) 
                    × (1 - market_regime_impact)
                    × (1 - implementation_friction)

三个成分的评估:

1. 信息泄漏影响 (information_leakage)
   - CPCV 虽然降低了泄漏，但仍有 20-40% 残余
   - 对于没用 CPCV 的回测，可能 30-60%
   
2. 市场制度影响 (market_regime_impact)
   - 2020→2025: 量化比例 20% → 50%，融资利率 1.5% → 3%
   - 综合影响: 收益率下降 20-30%（对应Sharpe下降30-40%）
   
3. 实施摩擦 (implementation_friction)
   - Paper: 模拟滑点，无融资成本，无风险限制
   - Live: 真实滑点，融资成本，风险限制
   - 预计成本差异: 0.5-1.5% 年化（对应Sharpe下降 5-15%）

示例计算:
backtest_sharpe = 2.0

信息泄漏: 2.0 × (1 - 0.30) = 1.4 ← 30%虚高
市场变化: 1.4 × (1 - 0.35) = 0.91 ← 35%市场变化影响  
摩擦成本: 0.91 × (1 - 0.10) = 0.82 ← 10%摩擦
最终预期: 0.82

复现率 = 0.82 / 2.0 = 41%（保守）
```

**验收标准**:
- [ ] 分别评估了三个成分的影响大小（有文献依据）
- [ ] 计算出了样本量下的置信区间
- [ ] 给出了分阶段的期望（第1周 vs 第4周 vs 完成后）
- [ ] 推荐的复现率范围是 40%-70%（而非 50%-80%）

**交付物**:
```
sharpe_replication_expectation_corrected.md

### P1-4: Paper Trading 最小样本量建议

**目标**: 基于统计学，给出"多长时间的Paper Trading 才能得出可靠结论"的明确答案

**方法论**:
```
Sharpe比率的样本量计算:

Sharpe 的标准误 = Sharpe / sqrt(N)

要使 95% 置信区间宽度 < 0.3，需要:
1.96 × (Sharpe / sqrt(N)) < 0.15
N > (1.96 × Sharpe / 0.15)²

示例（假设真实Sharpe=1.0）:
- N=20:  置信区间 [0.56, 1.44] (宽度0.88) ❌ 太宽
- N=50:  置信区间 [0.72, 1.28] (宽度0.56) △ 勉强
- N=100: 置信区间 [0.80, 1.20] (宽度0.40) ✓ 可接受
- N=150: 置信区间 [0.84, 1.16] (宽度0.32) ✓ 推荐
- N=250: 置信区间 [0.88, 1.12] (宽度0.24) ✓✓ 理想
```

**结论**:
```
根据回测Sharpe的预期，Paper Trading最少样本量：

回测Sharpe | 最少N (±0.2置信) | 推荐N | 周数
1.5        | 100              | 150  | 20周
1.0        | 220              | 250  | 50周
0.5        | 880              | 1250 | 250周

当前计划（4周）的足够性分析：
- 20个交易日
- 假设Sharpe=1.0：标准误≈0.22，置信区间[0.5,1.5] ❌ 完全不足
- 假设Sharpe=1.5：标准误≈0.15，置信区间[0.7,1.3] △ 仍然不足
- 假设Sharpe=2.0：标准误≈0.11，置信区间[0.8,1.2] △ 勉强

建议: Paper Trading 延长到 100+ 天（5个月）
```

**交付物**: 样本量与置信度的详细计算表 + 建议

| 样本量明显不足 | P1-4 确认100天仍不足 | 延长Paper时间到150-250天 |
| Sharpe复现率明显低于预期 | Live后实际<0.4 | 停止Live，回到Paper进行参数调优 |
